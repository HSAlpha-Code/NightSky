1. Double image decode in solve() — services.solve() calls load_image() to validate, then Tetra3Solver.solve() calls it again. Every upload is decoded twice, so the bomb cost and the 3000 px cost are both doubled for free.
2. No pixel guard on upstream images — tone.tame_jpeg, mosaic, hips_render all do Image.open(BytesIO(data)) on bytes fetched from ESASky/CDS. MAX_IMAGE_PIXELS protects the upload path only; a hostile or oversized upstream tile is unbounded.
3. panstarrs_hips.supports() ignores fov — it checks only dec >= -30, so it can be selected as a fallback for fields up to 120° where it can never work, burning a round trip and a CDS 400 each time.
4. _parse_filenames uses header.index(...) — an upstream header rename raises an uncaught ValueError → 500 instead of a ProviderError.
5. mast._pending is never cleared if the process dies mid-lookup — the landmark then reports has_hires: null forever on that instance, so the app polls a field that will never resolve.
6. One shared 500-entry locmem pool, culled by count only — 800 KB JPEGs and Detail objects compete in the same cache with no byte budget, so a sky-image workload evicts landmark details and vice versa.
7. Cache-Control: public, max-age=86400 on /api/sky-image is inert — it's a POST, so no browser or edge cache ever honours it; every request reaches the function. The header advertises a guarantee that doesn't exist.
8. The OOM 500 breaks the API's error contract — Vercel returns text/plain "A server error has occurred", not the {"error":{...}} envelope, so the app's _guard surfaces a parse failure rather than a retryable message.
